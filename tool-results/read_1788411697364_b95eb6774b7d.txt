   756→## S8 — Paper simulator unit tests (`paper/simulator.py`)
   757→- **Date:** 2026-09-04
   758→- **Scope:** NEW file
   759→  `mini-services/polymarket-bot/tests/test_paper_simulator.py` only. No

   764→### Background / investigation
   765→- `paper/simulator.py` exposes two pure helpers that govern every paper
   766→  fill: `_can_fill(order, book) -> float | None` (marketable-crossing test)
   767→  and `_apply_slippage(order, raw_price, book) -> float` (three-component
   768→  slippage model: flat 1-tick crossing + size-impact from book depth +
   769→  deterministic queue position via SHA-256 of `order.order_id`).
   770→- The simulator module constructs a module-level singleton
   771→  `paper_sim = PaperSimulator()` at import time, which reads
   772→  `store.paper_balance`. The shared `core.data_store.store` singleton
   773→  calls `load_from_disk()` on its own import, reading
   774→  `STORE_STATE_PATH` (default `/app/data/store_state.json`). Several other
   775→  modules reachable from `paper.simulator` (`core.decision_ledger`,
   776→  `core.audit_logger`, `core.market_db`, `core.safety`, `ml.model`,
   777→  `ml.vector_store`) each read their own env-var-configured DB / file path
   778→  at module load. Without redirecting these, the test would (a) hit
   779→  `/app/data/...` which does not exist in the sandbox (harmless — early
   780→  return from `load_from_disk`) and (b) potentially clobber the repo's
   781→  real `data/store_state.json` if `paper_sim` were ever exercised through
   782→  a code path that calls `save_to_disk()`. The test never calls
   783→  `save_to_disk`, but redirecting every env var to `/tmp/paper_sim_tests/`
   784→  up-front makes the file hermetic and resilient to future changes.
   785→- `_can_fill` is a regular method (uses `self` but reads no instance
   786→  state); `_apply_slippage` is a `@staticmethod`. Both are synchronous.
   787→  Tests therefore don't need `pytest-asyncio` — they construct minimal
   788→  `Order` + `OrderBook` fixtures inline and call the helpers directly,
   789→  which keeps the test surface tiny and the failure mode obvious.
   790→- The slippage model is **deterministic by `order_id`**: the queue
   791→  component is `SHA-256(order.order_id)[0] & 0x01` (0 or 1 tick). To pin
   792→  the queue component in tests (4), (5), and (7), I pre-computed order_id
   793→  literals whose first SHA-256 byte has LSB 0 (e.g. `paper-test-buy-6`
   794→  → 0x28, `paper-test-sell-0` → 0x6c, `paper-test-overflow-4` → 0x76) so
   795→  the slippage reduces to a known quantity (crossing + size-impact only)
   796→  and the assertions can be exact (`== pytest.approx(raw_price ± 0.01)`).
