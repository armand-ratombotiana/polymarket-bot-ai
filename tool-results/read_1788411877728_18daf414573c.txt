   923→## S8 — Paper simulator unit tests (`paper/simulator.py`)
   924→- **Date:** 2026-09-04
   925→- **Scope:** NEW file
   926→  `mini-services/polymarket-bot/tests/test_paper_simulator.py` only. No
   927→  existing source files edited — `paper/simulator.py`, `core/data_store.py`,
   928→  and the pre-existing `tests/conftest.py` + `tests/test_features.py`
   929→  (other subagents' work) are byte-identical before/after.
   930→
   931→### Background / investigation
   932→- `paper/simulator.py` exposes two pure helpers that govern every paper
   933→  fill: `_can_fill(order, book) -> float | None` (marketable-crossing test)
   934→  and `_apply_slippage(order, raw_price, book) -> float` (three-component
   935→  slippage model: flat 1-tick crossing + size-impact from book depth +
   936→  deterministic queue position via SHA-256 of `order.order_id`).
   937→- The simulator module constructs a module-level singleton
   938→  `paper_sim = PaperSimulator()` at import time, which reads
   939→  `store.paper_balance`. The shared `core.data_store.store` singleton
   940→  calls `load_from_disk()` on its own import, reading
   941→  `STORE_STATE_PATH` (default `/app/data/store_state.json`). Several other
   942→  modules reachable from `paper.simulator` (`core.decision_ledger`,
   943→  `core.audit_logger`, `core.market_db`, `core.safety`, `ml.model`,
   944→  `ml.vector_store`) each read their own env-var-configured DB / file path
   945→  at module load. Without redirecting these, the test would (a) hit
   946→  `/app/data/...` which does not exist in the sandbox (harmless — early
   947→  return from `load_from_disk`) and (b) potentially clobber the repo's
   948→  real `data/store_state.json` if `paper_sim` were ever exercised through
   949→  a code path that calls `save_to_disk()`. The test never calls
   950→  `save_to_disk`, but redirecting every env var to `/tmp/paper_sim_tests/`
   951→  up-front makes the file hermetic and resilient to future changes.
   952→- `_can_fill` is a regular method (uses `self` but reads no instance
   953→  state); `_apply_slippage` is a `@staticmethod`. Both are synchronous.
   954→  Tests therefore don't need `pytest-asyncio` — they construct minimal
   955→  `Order` + `OrderBook` fixtures inline and call the helpers directly,
   956→  which keeps the test surface tiny and the failure mode obvious.
   957→- The slippage model is **deterministic by `order_id`**: the queue
   958→  component is `SHA-256(order.order_id)[0] & 0x01` (0 or 1 tick). To pin
   959→  the queue component in tests (4), (5), and (7), I pre-computed order_id
   960→  literals whose first SHA-256 byte has LSB 0 (e.g. `paper-test-buy-6`
   961→  → 0x28, `paper-test-sell-0` → 0x6c, `paper-test-overflow-4` → 0x76) so
   962→  the slippage reduces to a known quantity (crossing + size-impact only)
   963→  and the assertions can be exact (`== pytest.approx(raw_price ± 0.01)`).
   964→
